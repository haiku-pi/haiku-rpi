### 2026-10-18 (night)
- **Flash lane proven**: netboot Linux → `wget | dd` 352 MB in 14 s → read-back SHA-256 match in 8 s,
  fully unattended (`sd-cycle.sh --flash`). The other project agreed we may overwrite the card;
  `restore-peer-sd.sh` puts their release image back.
- **H2 ✅ H3 ✅ on the real Pi 4 (4 GB, rev 0xc03111)**: firmware → U-Boot → `haiku_loader.efi` → kernel on
  **4 CPUs** → `PANIC: did not find any boot partitions!` → `kdebug>`, on UART and HDMI (Haiku boot
  splash + KDL on the EFI framebuffer). U-Boot hands over ~6 s before the panic; the ~58 s before it
  is the Pi's netboot attempt with no DHCP server.
- Upstream bugs found and fixed on `rpi4` (all generic, all needed for any EL2/U-Boot/clock-controller board):
  1. loader: a UART whose registers are not page aligned (BCM2835 mini UART +0x40) → "Too many levels at mapping" panic;
  2. loader: `_arch_transition_EL2_EL1` overwrote TTBR0/MAIR/VBAR_EL1 with EL2 values after they were
     programmed → secondaries released from the spin table ran with TTBR0 = 0 (stuck in
     `smp_cpu_rendezvous`); the boot CPU ran on U-Boot's MAIR;
  3. loader: spin-table release write + secondary data not cleaned to PoC (secondaries poll with caches off);
  4. loader: UART baud programmed from an unknown clock (-1) → keep firmware setup;
  5. PL011: the constructor's loopback test left IBRD=1/LCRH=0 (5-bit words) → garbage on real HW;
  6. FDT bus: `get_reg()` ignored parent `ranges` (all Pi peripherals sit behind /soc, emmc2bus, /scb).
- Found with QEMU raspi4b + QMP register dumps + gdbstub (`scripts/qemu-raspi.sh --gdbserver`), each fix
  then confirmed on hardware. QEMU ignores baud/word-length and caches: (4), (5), (3) were found by reading
  code for "what QEMU cannot show" before the first HW cycle.
